## 3. 费用勾稽规则（由账单原文定义）

账单第 1 页备注第 3、4 条原文：

> 工商业电费 = (1)市场化购电电费 + (2)上网环节线损费用 + (3)输配电费
> + (4)系统运行费 + (5)政府基金及附加；
> 本期电量 = 工商业电量 + 居民电量 + 农业电量；
> 本期电费 = 工商业电费 + 居民电费 + 农业电费 + 功率因数调整电费

### 3.1 核对关系 1：五项之和 = 工商业电费

| 月份 | 五项之和 | 账单工商业电费 | 差额 |
|---|---:|---:|---:|
| 2025-09 | `6708448.31` | `6708448.31` | `0.00` |
| 2025-10 | `5509070.05` | `5509070.05` | `0.00` |

### 3.2 核对关系 2：工商业电费 + 功率因数调整 = 本期电费

| 月份 | 工商业电费 | 功率因数调整 | 合计 | 账单本期电费 | 差额 |
|---|---:|---:|---:|---:|---:|
| 2025-09 | `6708448.31` | `-9206.37` | `6699241.94` | `6699241.94` | `0.00` |
| 2025-10 | `5509070.05` | `-37735.81` | `5471334.24` | `5471334.24` | `0.00` |

### 3.3 勾稽实现约束

1. **容差**：`Decimal("0.02")` 元。差额绝对值 ≤ 容差视为通过。
2. **超差处理**：生成告警并要求人工复核，
   **不得**自动修改任何原始账单金额（任务书 6.4）。
3. **参与字段必须全部非空**：任一参与项缺失时，
   勾稽**不成立**（状态记为未校验/需复核），**不得**用 0 代替缺失项参与计算。
4. **用电类别口径**：本账单为"用电户-110千伏-大工业用电"，
   `demand_charge` 与 `power_factor_adjustment_fee` 均为独立项，
   不并入五项之和。

## 4. 取数规则（来自真实排版踩坑）

以下每一条都来自 `REAL_BILL_VERIFICATION.md` 的实测特征，
是 P0-2 必须实现的防错规则：

| # | 规则 | 反例（实测） |
|---|---|---|
| R1 | **禁止取"标签后第一个数字"** | `工商业电费：用电户-110千伏-大工业用电-...` → 会取到 `-110`；`-35千伏` → 会取到 `-35` |
| R2 | 标签可能被换行截断，需支持跨行拼接后再匹配 | `工商业电费：` 与 `用电户-110千伏-...` 混排 |
| R3 | 数值可能在标签**之后若干行**，需按"标签 → 就近数值"窗口扫描 | `本期电量` ⏎ `8780498千瓦时` |
| R4 | 汉字之间可能被插入空格，匹配前需规范化 | `电 费 账 单`、`国 网 湖 北 省` |
| R5 | 数量与金额可能同行相邻，需按量纲与表头顺序区分 | `8780498 6708448.31`（前者 kWh，后者 元） |
| R6 | 小数点与小数位可能被切开 | `339059.` ⏎ `33` |
| R7 | 单位可能独立成行，需从表头区域解析并绑定 | `单位：千瓦时、千乏时、元、元/千瓦时…` |
| R8 | 同一字段可能在多处出现且数值不同，**不得静默选一个** | 第 1 页"本期电量"= `8780498`；第 2 页计量点 `8770300`、`8516838` |

**R8 的硬性要求**：正式总用电量
**只能取账单明确标注的权威字段**（`本期电量`），
**不得**由计量点电量或分时电量求和推导。任务书 10.1 第 7 条。

## 6. 测试夹具方案（脱敏要求）

任务书要求：不得把真实账单 PDF、客户名称、户号或地址提交到公开仓库。

**采用方案：内联最小文本片段（离线 fixture）**

| 项目 | 做法 |
|---|---|
| 形式 | 在测试模块中以字符串常量内联"最小必要文本片段" |
| 内容 | 仅保留包含**字段标签与数值**的行；删除户名、户号、地址、电能表编号、二维码说明等 |
| 脱敏检查 | 提交前用关键词扫描，确保不含 `户名`、`户号`、`用电地址`、`受电点`、电能表编号等实际值 |
| 优点 | CI 在 Python 3.11 / 3.14 上均可稳定运行，不依赖本机路径 |
| 标注 | fixture 顶部注明"来源于真实脱敏账单，已删除客户标识信息" |

**同时保留一个可选的"真实文件回归"入口**（不在 CI 强制）：
当本机存在账单目录时，用 `pytest.mark.skipif` 运行完整账单回归；
路径不存在时跳过并注明原因，**不得**因此让 CI 失败，也**不得**把跳过算作通过。

## 7. 与既有数据模型的关系

本基线的字段最终落入 P0-4 的新表，但**不改变**第一阶段已冻结的 `BillRecord` 语义：

- `total_energy_kwh` ← `total_consumption`
- `total_amount_yuan` ← `bill_total_amount`
- 发票金额、各项费用、平均电价、需量电费等为**新增字段/新增表**，
  不得挤进现有字段或合并为一个字符串。

金额精度：第一阶段 `BillRecord` 的金额列为 `REAL`。
P0-4 需评估是否改为精确十进制存储（如整数分或 TEXT 存十进制字符串），
该决策在 P0-4 设计时给出，本轮不修改数据库结构。
