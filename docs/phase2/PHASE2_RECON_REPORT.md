且**户号、户名与任务书所列为不同客户**（此处为岚图汽车科技/东风汽车武汉分公司）。

**这些文件不得提交到公开仓库**（含客户名称、户号）。已将它们置于仓库之外，
仅作本地回归素材，并在 `.gitignore` 中确保 `*.pdf` 不被纳入。

### 3.2 文本提取的已知难点（实测发现）

真实账单文本存在以下特征，直接影响 P0-2 规则解析，需提前记录：

1. **数字被换行截断**：`419446 339059.\n33` → 实为 `339059.33`；
   `输配需量电费 2143.225806 83585.81` 中数量与金额同行混排。
2. **汉字间被插入空格**：`国 网 湖 北 省 电 力 公 司`、`电 费 账 单`。
3. **多列文本被压成一行**，列边界丢失（表格结构无法直接从文本位置恢复）。
4. **单位行独立**：`单位：千瓦时、千乏时、元、元/千瓦时…`。

结论：P0-2 不能依赖简单行内正则，必须结合"字段标签 + 上下文 + 金额校验"的规则集，
且必须把"无法确定"的情形交给人工复核——与任务书 5.4 的要求一致。

## 10. 对第一阶段的风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 新增 PDF 依赖 | 可能破坏分层守卫测试与包导入测试 | 依赖只进入 `infrastructure`；扩展 `test_layering.py` 显式禁止 `domain`/`calculations` 导入 |
| 数据库结构变更 | 可能破坏既有项目数据 | 必须走真实迁移 + 版本提升；先写迁移失败回滚测试；不得重建库 |
| `ProcessingStatus` 扩展 | 触碰 `CHECK` 约束，旧库写入新状态会失败 | 迁移中重建约束或新增列；迁移前后各跑一次全量测试 |
| 界面改动 | 可能影响既有项目 CRUD 与消纳演示 | 新功能独立区域；P0-1 不改界面，降低首轮风险 |
| 金额精度 | `REAL` 存储与任务书要求的精确金额冲突 | P0-2/P0-4 引入 `Decimal` 与对应列类型；先在领域层用 `Decimal` |
