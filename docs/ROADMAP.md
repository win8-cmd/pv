# CENEP 分阶段开发路线图（ROADMAP）

- 软件名称：CENEP —— 中国工商业分布式光伏项目经济评价软件
- 当前版本：`0.1.0`，当前阶段：第一阶段：工程骨架与核心规则冻结
- 配套文档：`docs/PRD.md`（产品需求）、`docs/CALCULATION_SPEC.md`（计算口径）

> **本仓库当前状态：第一阶段已完成，尚未开始第二阶段开发。**
> 仓库中不存在第二阶段及以后阶段的任何实现代码；凡未在本文件标注"已完成"的能力，
> 均不得在界面、报告或对外说明中描述为已具备。

## 2. 第一阶段：工程骨架与核心规则冻结（已完成）

### 2.1 开发目标

建立分层模块化单体架构并由自动化测试守住依赖方向；冻结领域实体契约与数据库模式；把逐时段光伏消纳计算做对做透并形成唯一权威口径说明；打通"界面 / 命令行 → 应用服务 → 领域计算 → SQLite 持久化"的最小闭环。

### 2.2 实际交付物

| 交付物 | 位置 | 内容 |
|---|---|---|
| 分层包结构 | `src/cenep/` | `domain`、`calculations`、`application`、`infrastructure`、`ui` 五层；依赖方向：表现层 → 应用服务层 → 领域层 |
| 版本与阶段常量 | `src/cenep/__init__.py` | `__version__ = "0.1.0"`、`APP_NAME`、`STAGE` |
| 领域数据模型 | `src/cenep/domain/models.py` | 11 个实体契约：Project、Document、BillRecord、LoadProfile、TariffModel、PVModel、Scenario、CalculationRun、ResultRecord、ValidationIssueRecord、Report；UUID4 主键、UTC ISO 8601 秒级时间戳、单位约定；`CALCULATION_ENGINE_VERSION = "0.1.0"`、`ASSUMPTIONS_VERSION = "2026.02-stage1"` |
| 校验与异常 | `src/cenep/domain/validation.py`、`exceptions.py` | 电量序列 7 条合法性规则、项目字段 5 条校验、稳定问题代码、四类数据质量提示；校验错误携带结构化问题清单 |
| 消纳计算 | `src/cenep/calculations/self_consumption.py` | `CALCULATION_VERSION = "0.1.0"`；自用/上网/购电逐时段拆分；三个比例指标与零分母处理；能量守恒自检；输入指纹 |
| 计算口径说明书 | `docs/CALCULATION_SPEC.md` | 输入定义、公式、指标、边界情形、标准验收案例、规则边界 |
| SQLite 持久化 | `src/cenep/infrastructure/database.py` | `SCHEMA_VERSION = 1`；11 张业务表与索引一次建好；外键开启；`BEGIN IMMEDIATE` 事务与回滚；参数化 SQL；`RESTRICT` 删除策略；项目仓储完整增删改查 |
| 应用服务与界面 | `src/cenep/application/project_service.py`、`src/cenep/ui/main_window.py` | 项目用例、写前校验、消纳计算调用、阶段元信息（不写 SQL、不含公式）；项目列表增删改查、消纳计算输入与结果展示、未开放功能声明 |
| 应用装配与命令行 | `src/cenep/app.py`、`cli.py`、`config.py` | 统一 GUI 入口；命令 `init-db`、`project-add/list/show/update/delete`、`self-consumption`（支持 `--json`）、`gui`、`info`；数据库路径优先级：参数 > `CENEP_DB_PATH` > `%LOCALAPPDATA%\CENEP\cenep.db` |
| 测试套件 | `tests/` | 244 个用例全部通过（第一阶段基线），覆盖校验、消纳计算、持久化、界面装配、分层隔离 |

### 2.3 验收门槛（已全部达成）

1. 在 Windows + Python 3.14.7 环境下执行 `python -m pytest`，244 个用例全部通过（第一阶段基线）。
2. 领域层与计算层不导入 PySide6、sqlite3、pandas、numpy、openpyxl 及任何 PDF/OCR 库，也不依赖其他分层。
3. 界面层不含业务公式、不含 SQL，必须通过应用服务访问业务能力；核心路径不存在未实现占位与空实现函数。
4. `python -m cenep.cli self-consumption --load 3,8,2 --pv 5,4,2 --interval 60` 输出自用 9 kWh、上网 2 kWh、购电 4 kWh、自用率 9/11、负荷覆盖率 9/13、余电比例 2/11。
5. 项目新增后重启程序仍能从 SQLite 读回，列表刷新自数据库而非内存；删除存在关联数据的项目会被数据库拒绝并转为应用层可识别的错误。

### 2.4 风险与技术难点

| 风险 / 难点 | 说明 |
|---|---|
| 界面层偷写公式 | 界面最容易图省事直接算比例，已用代码扫描测试拦截 |
| 数据契约过早变动 | 全量建表降低了后续改表成本，但字段落库后仍需迁移策略；第一阶段冻结以换取稳定性 |
| 浮点求和误差 | 使用 `math.fsum`，并在计算层内部自检守恒关系，容差仅用于浮点误差 |
| 单文件膨胀 | 架构测试限制单文件不超过 1200 行，避免核心逻辑堆在一个模块 |

## 3. 第二阶段：电费账单导入与数据提取

### 3.1 开发目标

把业主提供的电费账单从"图片 / PDF 附件"变成可查询、可校验、可复核的结构化记录，并让每一份数据都带上来源与精度标注。

### 3.2 前置条件与交付物

| 类型 | 条目 | 说明 |
|---|---|---|
| 前置条件 | 第一阶段通过验收 | 已满足 |
| 前置条件 | 账单样本与字段清单 | 收集覆盖不同地区、不同用户类型、不同版式的真实账单；首版提取账期起止、总用电量、总电费金额、峰平谷电量、基本电费、力调电费 |
| 前置条件 | 人工复核流程 | 明确"识别结果一律默认为未校验" |
| 交付物 | 账单文件登记 | 文件元数据与解析结果分离存储，记录处理状态 |
| 交付物 | 账单字段提取 | 从结构化程度高的账单（Excel、文本型 PDF）提取关键字段 |
| 交付物 | 人工复核与修正界面 | 逐字段确认、修改、标记，确认前数据保持未校验状态 |
| 交付物 | 校验状态标注 | 未校验、有效、无效、存疑四态贯穿账单生命周期 |
| 交付物 | 缺失值处理与质量报告 | 无法识别的费用项保持空值，不使用 0 填充；汇总每个项目的账单覆盖月份、缺失项与可疑项 |
| 交付物 | 测试 | 账单样本回归测试与缺失值处理测试 |

### 3.3 验收门槛

1. 账期、总用电量、总电费三项提取准确率满足设定目标，且错误可被人工复核发现。
2. 无法识别的字段在数据库中为空值，验证不存在被填 0 的记录；每份账单都能追溯到来源文件与导入时间。
3. 未校验数据不会被后续测算当作已核实数据使用；账单数据只作为月度累计值存储，不因"看起来像曲线"而被用于逐时消纳计算。
4. 新增测试全部通过，既有 244 个用例无回归。

### 3.4 风险与技术难点

| 风险 / 难点 | 说明 |
|---|---|
| 账单版式差异极大 | 各省市、各供电公司模板不同，纯规则解析难以覆盖，需要版式归并策略 |
| 扫描件质量与误读 | 歪斜、印章遮挡、低分辨率显著降低识别率；金额误读后果严重，必须强制人工复核 |
| 费用项命名不统一 | "基本电费""需量电费""容量电费"混用，需要统一映射字典；力调电费等分项常不单列，须记为缺失而非 0 |
| 依赖引入边界 | 解析库只能出现在基础设施层，不得被领域层与计算层导入 |

## 4. 第三阶段：负荷与电价分析

### 4.1 开发目标

建立精度等级明确的负荷数据与四要素齐全的分时电价方案，并按逐时段可避免的购电边际成本测算光伏自用收益。

### 4.2 前置条件与交付物

| 类型 | 条目 | 说明 |
|---|---|---|
| 前置条件 | 第二阶段通过验收 | — |
| 前置条件 | 负荷数据来源确认 | 具备电表分时计量数据，或明确采用账单分摊估算方案并接受其精度等级 |
| 前置条件 | 电价文件与时段口径 | 收集目标地区正式电价文件（含文号或官方发布渠道），确认峰平谷边界、是否含尖峰、季节性调整规则 |
| 交付物 | 负荷数据导入与来源标注 | 统一到声明的时间粒度与计量边界；区分实测、账单分摊、模拟、人工录入四类来源 |
| 交付物 | 月度分摊功能 | 把月度电量按典型曲线分摊为估算曲线，结果显式标注为估算 |
| 交付物 | 分时电价方案 | 地区、生效日期、适用用户类型、来源说明、时段划分与电价水平；来源为空或未核实的方案不能置为启用 |
| 交付物 | 逐时段自用收益 | 自用电量按对应时段购电边际成本计价 |
| 交付物 | 固定费用单列 | 基本电费、需量电费、功率因数调整及其他费用独立成项，默认不随电量减少 |
| 交付物 | 测试 | 时段对齐、跨零点边界、电价生效期切换、缺失电价与零分母场景 |

### 4.3 验收门槛

1. 每一项电价数据都具备地区、生效日期、适用用户类型与来源说明；缺任一项的方案无法启用。
2. 自用收益逐时段对齐计算，实现中不存在用年平均电价替代分时电价的计算路径。
3. 基本电费与需量电费不被按发电量比例扣减，输出中与电量电费分列。
4. 负荷数据在界面与结果中始终显示来源类型；估算曲线不得与实测数据使用同一标识。
5. 时间粒度与计量边界不一致的输入被拒绝并给出明确问题说明；同一输入重复执行结果完全一致。
6. 新增测试全部通过，既有测试无回归。

### 4.4 风险与技术难点

| 风险 / 难点 | 说明 |
|---|---|
| 电价政策复杂且有地区差异 | 峰谷时段、季节性、代理购电价格波动，需要可配置而非硬编码的模型 |
| 时段边界处理 | 跨零点时段、时段长度不一致的对齐是常见错误来源 |
| 账单分摊引入的误差 | 分摊曲线本身是假设，必须让使用者看到误差范围而非一个精确数字 |
| 需量电费是否变化 | 取决于实际需量曲线与合同约定，无法一概而论，只能单列并提示 |
| 电价核实成本与精度混用 | 逐地区人工核验工作量大，须显式标注"未核实"；实测与估算混入同一指标会造成误导，需要强标识 |

## 5. 第四阶段：发电量模拟

### 5.1 开发目标

在缺少实测发电数据时，用物理模型生成可信的逐时发电量曲线，并让模拟结果与实测数据能够被明确区分。

### 5.2 前置条件与交付物

| 类型 | 条目 | 说明 |
|---|---|---|
| 前置条件 | 第三阶段通过验收 | — |
| 前置条件 | 气象数据来源 | 确定来源与获取方式，明确其许可与离线使用限制 |
| 前置条件 | 系统参数清单 | 组件型号与衰减、逆变器效率、倾角与方位、遮挡与线损；已有可用于对比验证的参考发电数据 |
| 交付物 | 逐时发电量模拟 | 引入 `pvlib`，按容量、倾角、方位、系统效率模拟逐时发电量 |
| 交付物 | 系统参数配置 | 参数集中管理并版本化，纳入假设版本号 |
| 交付物 | 模拟结果标注 | 模拟曲线来源类型明确，与实测、账单分摊数据区分 |
| 交付物 | 逐年发电量预测 | 含首年发电量与逐年衰减，为后续现金流提供输入 |
| 交付物 | 对比校验与测试 | 模拟曲线与参考数据的偏差分析；参数边界、零容量、全遮挡、跨年天数与闰年处理 |

### 5.3 验收门槛

1. 模拟发电量与参考数据在约定指标上的偏差在设定阈值内；超限时报告明确指出而不隐藏。
2. 模拟输入参数全部可追溯，参数变更会改变假设版本号与结果标识；模拟结果在存储与展示中始终标注为模拟数据。
3. 模拟逐时曲线可直接作为消纳计算输入，且与负荷曲线粒度一致。
4. 新增依赖只出现在允许的层，架构测试继续通过；新增测试全部通过，既有测试无回归。

### 5.4 风险与技术难点

| 风险 / 难点 | 说明 |
|---|---|
| 气象数据可得性与授权 | 逐时辐照数据来源有限，离线场景需要预置数据并处理授权 |
| 模型对实际屋顶的简化 | 遮挡、污损、朝向差异难以完全建模，模拟值不应被当作实测值 |
| 参数敏感性高 | 倾角、方位、系统效率的小幅变化会显著影响年发电量，需要敏感性提示 |
| 计算耗时与财务耦合 | 全生命周期逐年计算耗时明显；衰减曲线直接影响现金流，两者口径必须一致并共同版本化 |

## 6. 第五阶段：经济评价与现金流

### 6.1 开发目标

在电量与电价结果正确的前提下，产出可直接用于投资评审的财务指标：现金流、净现值、内部收益率与投资回收期，并支持关键因素的敏感性分析。

### 6.2 前置条件与交付物

| 类型 | 条目 | 说明 |
|---|---|---|
| 前置条件 | 第四阶段通过验收 | 或发电量数据可由外部导入并标注来源 |
| 前置条件 | 投资与运营口径 | 初始投资构成、资金来源与利率、建设期；运维费率、保险、人工、备件、逆变器更换周期 |
| 前置条件 | 税务口径 | 增值税、企业所得税、附加税及适用优惠政策的适用条件 |
| 交付物 | 初始投资与运营成本模型 | 设备、施工、设计、并网等分项投资；逐年运维、保险、更换与残值处理 |
| 交付物 | 现金流表 | 逐年现金流入流出与累计现金流 |
| 交付物 | 财务指标 | 净现值、内部收益率、投资回收期，含折现率与计算期的显式记录 |
| 交付物 | 税务处理与敏感性分析 | 按确认口径处理增值税与所得税，不臆造优惠政策；给出关键因素变动对指标的影响 |
| 交付物 | 结果留痕与测试 | 指标落库为结果记录并关联计算运行记录，支持按版本复现；含手工核算对照、边界条件、内部收益率无解与多解处理 |

### 6.3 验收门槛

1. 现金流逐年闭合：每年现金流入减流出等于净现金流，累计值可由净现金流累加复现。
2. 指标可手工核算复现，与软件输出在约定精度内一致。
3. 内部收益率无解或多解时给出明确提示，不返回一个看似正常的数字。
4. 每一条财务结果都能追溯到计算运行记录、输入快照、计算规则版本与假设版本。
5. 电价与发电量的假设变化会同步反映在结果标识中，历史结果不被新口径重新解释。
6. 新增测试全部通过，既有测试无回归。

### 6.4 风险与技术难点

| 风险 / 难点 | 说明 |
|---|---|
| 税务规则地域与时间差异 | 优惠政策随年份与地区变化，必须可配置并标注适用条件 |
| 内部收益率的数值特性 | 现金流符号多次变化时可能多解，需要显式判定与提示 |
| 电价长期走势假设 | 长期电价预测缺乏可靠依据，只能作为可调假设并显著标注 |
| 精度与口径传导 | 上游电量或电价的精度等级会传导到财务结论，结果必须携带数据质量标签 |
| 结果解释风险 | 财务数字易被当作承诺，界面与报告需明确其为测算值 |

## 7. 第六阶段：方案对比与报告输出

### 7.1 开发目标

支持多套装机与电价组合的横向比选，并把测算过程与结论输出为可交付的报告。

### 7.2 前置条件与交付物

| 类型 | 条目 | 说明 |
|---|---|---|
| 前置条件 | 第五阶段通过验收 | — |
| 前置条件 | 报告结构与模板规范 | 明确必须披露的假设、数据来源与精度等级 |
| 前置条件 | 对比维度与排序准则 | 明确不以软件自动结论替代人工判断 |
| 交付物 | 测算方案管理 | 光伏方案与电价方案的组合管理与状态流转 |
| 交付物 | 多方案对比 | 关键电量、收益与财务指标的并列比较 |
| 交付物 | 数据质量报告 | 每个方案的输入来源、缺失项与校验状态汇总 |
| 交付物 | 报告导出与溯源信息 | 可行性研究报告以 Excel 与 PDF 双格式输出，内嵌计算规则版本、假设版本与输入指纹 |
| 交付物 | 测试 | 报告数字与计算结果一致性校验、模板渲染测试 |

### 7.3 验收门槛

1. 报告中每一个数字都能在软件计算结果中定位到对应指标，不存在报告独有算法。
2. 报告自动列出输入数据来源类型、缺失项与未核实项，不隐藏数据缺陷。
3. 导出文件在无软件环境的机器上可正常打开与阅读；同一输入重复导出，报告数字完全一致。
4. 未实现的评价内容不出现在报告中，不预留空章节；新增测试全部通过，既有测试无回归。

### 7.4 风险与技术难点

| 风险 / 难点 | 说明 |
|---|---|
| 报告模板多样性 | 不同投资方要求的格式不同，模板体系需可扩展 |
| 数字一致性 | 报告与界面若各自计算会出现不一致，必须共用同一计算结果 |
| 中文排版与表格 | Excel 与 PDF 的表格换行、精度位数与单位标注容易出错 |
| 数据披露尺度 | 需在完整披露假设与保护业主数据之间取得平衡 |

## 8. 第七阶段及以后：屋面三维、储能、电力交易、多用户

### 8.1 开发目标

把能力从"电量与财务测算"扩展到空间、储能、市场与协同四个方向，按子能力分别立项、分别验收，不做捆绑式大版本。

### 8.2 前置条件与交付物

| 类型 | 条目 | 说明 |
|---|---|---|
| 前置条件 | 第六阶段通过验收 | — |
| 前置条件 | 试点与合规边界 | 各子能力分别具备真实试点项目与可验证的参考结论；明确数据来源、合规边界与责任划分 |
| 交付物 | 屋面识别与自动排板 | 从影像或图纸提取可用屋面区域，生成组件排布方案与装机容量 |
| 交付物 | 三维展示 | 屋面、组件与遮挡关系的三维可视化 |
| 交付物 | 储能充放电优化 | 储能容量配置与充放电策略优化，纳入现金流 |
| 交付物 | 电力市场交易优化 | 市场化电价条件下的交易策略测算 |
| 交付物 | 用户权限与云端协同 | 多用户、角色权限与项目数据共享 |
| 交付物 | 安装包 | Windows 可安装分发包与升级机制 |

### 8.3 验收门槛

1. 每个子能力独立设定可量化门槛，并在真实试点项目上验证后才标记为可用。
2. 新增能力不得破坏既有数据隔离与可追溯性：每条结果仍携带来源与版本信息。
3. 三维与图像类能力不得把识别结果直接当作设计成果，需保留人工确认环节。
4. 云端与多用户能力必须明确数据归属、权限边界与离线降级行为。
5. 安装包需在无开发环境的 Windows 机器上完成安装、启动、测算与导出的完整流程验证。
6. 全部既有测试保持通过。

### 8.4 风险与技术难点

| 风险 / 难点 | 说明 |
|---|---|
| 图像识别精度 | 屋面边界与障碍物识别误差直接影响装机容量与发电量 |
| 三维性能 | 大屋面模型的渲染与交互性能需要专门优化 |
| 储能策略收益不确定性 | 策略收益依赖电价机制与运行工况，难以给出稳定结论 |
| 市场规则的时效性 | 交易规则与价格机制变化快，模型需快速迭代并标注适用期 |
| 数据合规与安全 | 云端协同涉及业主用电数据，需明确授权、脱敏与存储边界 |
| 范围蔓延 | 子能力跨度大，必须坚持分别立项与分别验收 |

## 9. 阶段推进纪律

1. 前一阶段验收门槛未全部达成前，不启动下一阶段的正式开发。
2. 每阶段新增能力必须同步补充测试，并在提交前实际运行完整测试套件。
3. 任何影响计算结果的口径变化，必须按 `docs/CALCULATION_SPEC.md` 第 11 节提升版本号并修订该文件。
4. 未实现的能力不得出现在界面、报告或对外材料中；界面必须显式声明尚未开放的功能。
5. 数据来源与精度等级的标注能力必须领先于对应测算能力上线，避免先出结论后补证据。
